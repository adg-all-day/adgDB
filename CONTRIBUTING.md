# Contributing to adgDB

Thank you for your interest in improving adgDB. Contributions of all kinds — code, documentation, testing, and design feedback — are welcome and appreciated.

By participating in this project, you agree to uphold our [Code of Conduct](CODE_OF_CONDUCT.md) and the Contributor License Agreement (CLA).

## Before You Begin

- Review open [issues](https://github.com/adg-all-day/adgDB/issues) to see whether your idea is already being discussed.
- For significant changes, consider opening an issue first to align on approach before investing time in an implementation.

## Contribution Workflow

1. **Fork** the repository to your own GitHub account.
2. **Clone** your fork locally:
   ```bash
   git clone https://github.com/adg-all-day/adgDB.git
   ```
3. **Branch** from the default branch, using a descriptive name:
   ```bash
   git checkout -b feature/your-feature
   ```
4. **Implement** your changes in the codebase.
5. **Test** your work. Ensure new code is covered and that the existing suite continues to pass.
6. **Commit** with a clear, descriptive message:
   ```bash
   git commit -m "Add a brief description of your changes"
   ```
7. **Push** the branch to your fork:
   ```bash
   git push origin feature/your-feature
   ```
8. **Open a Pull Request** against the original repository, describing the motivation and scope of your changes.
9. **Iterate** on reviewer feedback. Address requested changes; further discussion is a normal part of the process.
10. **Merge.** Once approved and all feedback is resolved, a maintainer will merge your contribution.

## Code Style

Maintain consistency with the surrounding code. Where the project does not specify an explicit convention, follow generally accepted practice for C and the tooling in use.

## Reporting Issues

If you encounter a bug or have a feature suggestion, please open an issue and include enough detail to reproduce or evaluate it — expected behaviour, actual behaviour, and relevant environment information.
